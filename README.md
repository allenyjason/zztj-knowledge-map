# 资治通鉴 · 知识图谱

把《资治通鉴》全二百九十四卷的人、事、关系，压缩成一个可以在浏览器里直接打开的单文件交互图谱。

不用装环境、不用起服务、不用联网，双击 `index.html` 就能看。

> 完全离线可用——拷到 U 盘、断网打开都能正常运行。

---

## 它是什么

《资治通鉴》是编年体史书，人物散落在 1362 年、294 卷的流水账里。想看清「谁和谁是什么关系」「一件事背后牵扯了多少人」，靠翻书几乎不可能。

这个项目把全书抽成一张**人物关系网络**：

- **19,843 位人物**，其中 20 位是「臣光曰」里的论赞人物，单独标记
- **46,535 条关系**（君臣、父子、攻伐、举荐、谗杀、师承……）
- **24,287 件史事**，每件标注年份、参与人、地点
- **799 个地点**、**36 个政权实体**、**563 条同名异人消歧说明**

时间跨度从**公元前 454 年**到**公元 959 年**，约 315 万字原文。

## 怎么用

### 打开

```
双击 index.html
```

或者用任意现代浏览器打开。**无需联网**——所有资源都在文件内，断网、拷 U 盘、发微信都能直接用。

### 三个核心操作

**① 按年份收敛**

左侧「年份区间」拖动滑块，或用「全」按钮一键回到全书范围。也可以点下方的**卷目树**（周纪一、秦纪一、汉纪一……共 294 卷）或**朝代行**（一键圈定该朝代全部卷）。

> 点卷或朝代时，区间会前后各放宽 5 年——因为人物的活跃期常横跨卷界（比如某人物「活动于前 445–前 359」，而卷界是前 403）。

**② 按中心人物展开**

在搜索框输入人名，或在图上点任意节点，即以该人为中心按「间接关联级数」展开子图。级数 2 级＝朋友的朋友。

**③ 「资」字布局**

右上角点「**资**」按钮，节点会沿一幅草书「资」字的笔迹重新排布；再点一次恢复力导向自由布局。

> 字形取自一幅草书「资」字手稿，逐点提取：228 个采样点，每点带粗细权重（0.121–0.537），笔顺按草书的提按节奏还原——顶部横画与底部贝环重按，右上转折与长撇提笔见锋。

### 右侧面板

| 标签页 | 内容 |
|---|---|
| 同期大事 | 当前年份区间内的事件、关系、活跃人物榜单 |
| 专题大事 | 100 件人工指定的重大事件，点「定位」一次设好时间+中心人物 |
| 事件时间轴 | 按年排列的事件流 |
| 消歧难点 | 563 条同名异人说明（如三个「王成」、两个「徐邈」） |

## 配色：五德终始

节点颜色按**五德终始说**（邹衍的王朝德运理论）分配，不是随便挑的：

| 德运 | 正色 | 对应政权 |
|---|---|---|
| **水** | 黑 / 深蓝 | 秦（始皇尚黑）、汉（承秦水德）、北魏、匈奴、突厥 |
| **火** | 赤 | 周（尚赤）、蜀汉（炎汉）、隋、宋、明、西楚 |
| **木** | 青 | 东吴、北齐、北周、南齐、梁、陈 |
| **土** | 黄 | 唐（土德）、曹魏（土德代汉火）、新、后唐 |
| **金** | 白 | 晋、西晋、后晋、代 |

同代不同政权靠**明度分层**区分。比如同为木德的六个南朝政权：

```
东吴 #2b8c59 · 北齐 #4a8f5a · 北周 #2e7d5b · 南齐 #5c9c6a · 梁 #3d7a7a · 陈 #2a6b4a
```

**为什么汉用黑色而不是黄色？** 汉初承秦制，张苍主张水德；武帝太初改历后才改土德。这里取水德黑色，一是符合「汉承秦」的史实起点，二是黑色在浅绿底图上对比最强，而汉朝有 2,496 人，是全书最大的一片。

> 水德「尚黑」若用纯黑，两千多人会糊成一团。所以取**近黑的深蓝灰**（如汉 `#4a5a6e`），保留「黑」的意象又看得清。

## 数据从哪来

原文是《资治通鉴》二百九十四卷的通行本。抽取流程：

```
原文分段 → 实体识别（人名/地名/政权）→ 关系抽取 → 同名消歧 → 交叉校验
```

加工后的人工校验重点：

- **同名异人**：563 条消歧条目。比如「王成」有西汉胶东相（前 67 年在任）和东汉顺帝时人（125 年），跨 190 年，必须分开。
- **生卒年**：逐一核对，如王莽定为前 45 — 公元 23（新地皇四年为绿林军所杀）。
- **政权归属**：`power` 字段记录人物所属朝代。同名不同代按年份与文本拆分——曹魏/北魏/东魏/西魏、蜀汉/成汉/后汉/南汉、宋（刘）/南齐/梁/陈。

## 技术实现

**单文件架构**。所有数据、样式、逻辑都内联在一个 HTML 里，没有任何构建步骤。

| 部分 | 说明 |
|---|---|
| 数据 | 内联 JSON，18 个字段的 `DATA` 对象 |
| 渲染 | 力导向图 + SVG |
| 布局 | 力导向（link / charge / collide / center）或字形笔迹解锁 |
| 字体 | 系统字体栈，无外部字体 |
| 依赖 | 无，全部内联 |

零外部请求、零构建步骤。

### 性能设计

46,535 条关系全量渲染会卡死。做法是：

1. **默认上限 500 节点**——按「重大事件锚点 → 中心距离 → 关联度」三级优先截取
2. **BFS 子图**——选中心人物时只展开其 N 级内邻域
3. **密度自适应**——按节点数动态缩放点径、碰撞半径、连线距离与斥力，让「点半径 ÷ 平均间距」稳定在 0.15–0.20

> 密度自适应解决的是：周纪 300 个点铺得开、汉纪 500 个点挤成一团的问题。缩放手系 = 平均间距 / 50px，钳制在 0.42–1.5。
